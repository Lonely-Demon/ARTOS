# IDREA NeX-Gen Robotics Challenge

This directory is the ARTOS project workspace for the IDREA NeX-Gen Robotics Challenge. It is a bounded application of the Universal Virtual Enterprise framework, not a replacement for the canonical architecture. The project began from the referenced task `80HbnErd57jvZt90n0TbkD`, whose source artefacts are preserved under `source/referenced-task-80HbnErd57jvZt90n0TbkD/`.

## Current operating rule

The project must follow the Universal Enterprise sequence. It must accept the supplied challenge as the starting input, reconstruct and verify the problem and operating context, map the relevant landscapes, build the factor/evidence/dependency catalogue, derive requirements and success conditions, compare architecture families, preserve decisions and disagreement, produce the canonical technical concept, validate it, and only then compress it into competition submissions.

The project must not jump directly from a plausible reading of the rulebook to an adhesion mechanism, chassis, or selected architecture. Candidate mechanisms remain hypotheses until the relevant evidence, constraints, interfaces, failure modes, resource consequences, and evaluation conditions have been established.

## Source hierarchy

The official IDREA challenge page and technical rulebook are the primary sources for competition facts. The user’s stated constraints and strategy are authoritative for project intent. The inherited task artefacts are historical project evidence and working material, not automatically verified fact. External research, calculations, simulations, and physical tests must be recorded with provenance and evidence state.

## Evidence labels

Each material claim should be labelled as one of: **verified official**, **verified external**, **measured locally**, **derived calculation**, **design inference**, **hypothesis**, **estimate**, **open**, or **excluded**. A plausible engineering statement is not an official requirement until its source and status are recorded.

## Immediate project phase

The project is at corrected **Stage 0–2**: frame the supplied challenge, verify the literal rulebook, reconstruct the actual problem and operating context, and map the decision space. No architecture family is selected. The existing suction/airflow, multi-modal adhesion, and soft-reconfigurable families are retained only as candidate hypotheses for later comparison.
